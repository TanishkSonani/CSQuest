# Private Library

## Sharing and access

Signup always creates a **Learner**. Open **Admin → Users & Access** to search all accounts, select one or many, and show/hide Library for those learners. Learners with access can browse, play, download and keep personal notes/favorites; only **Admins** manage files, folders and public links. Library is hidden from other learners on desktop and mobile, and the API rejects access independently. Existing Editor grants become view-only. The configured root administrator can promote/demote other Admins; this root cannot be demoted or self-deleted. Changes reach open sessions within 30 seconds, and fresh API requests enforce current permissions immediately. All members share the same Library and allocations. Physical storage details are Admin-only.

Select a completed file **or directory**, then **Details → SHARE FILE / SHARE DIRECTORY** to create a public link lasting 1, 7, 30 days or indefinitely. The standalone page allows playback, previews and downloads without login. A directory link includes its descendants and future additions; parents, siblings and other drives stay private. Move an item outside that directory to remove it from that link's scope. Manage access can revoke or replace links. Tokens are shown only when generated; PostgreSQL stores SHA-256 hashes. Deleting a shared item invalidates its link.

Anyone who receives a public link can use it until it expires or is revoked. Pages and responses request no indexing or referrer forwarding. Revocation blocks subsequent requests; bytes already downloaded or buffered cannot be recalled. Sharing does not grant access to learning records or other platform features.

The upload queue is automatic: up to **four files** transfer concurrently, each extra file shows its queue position and starts as soon as any active file frees a slot. Select additional files while a batch is running to append them. The entire new selection must pass storage preflight and atomic reservation before it enters the queue. Canceled and failed transfers release their active slot so the next queued file can start. Reloading requires reselecting the original files to resume; browser file handles cannot be recovered automatically after a reload.

Open **Library** in the sidebar or **More → Library** on mobile. The **This PC** overview follows File Explorer's layout while using CSQuest's theme. Boot has a **35 GiB** library allocation and Block has **125 GiB**. Select a drive to browse folders, search/sort files, switch list/grid views, upload, download, rename, or delete. Individual folder deletion requires an empty folder; bulk deletion can permanently remove a selected directory tree after explicit confirmation.

The UI uses decimal **KB, MB, and GB** throughout. The original byte limits are unchanged: they display as **37.58 GB Boot** and **134.22 GB Block**. On desktop a single click selects a drive or item; double-click opens a drive, folder, or media file. Enter opens a focused item. Mobile uses one tap to open. Opening a drive replaces the overview with a directory explorer, breadcrumbs, an Up button, and a desktop folder navigation pane.

Selecting a file on desktop shows its **Details** panel. Use the **Details** icon on mobile. Details include exact byte size and formatted size, extension/type, storage, folder location, creation/library-change dates, stored-file modification date, and allocated disk size where the OS supplies it. Supported media also exposes duration and video dimensions, read through the browser's metadata loader without transcoding. Folder details show child counts. Metadata unavailable to the browser is labeled unavailable.

Each drive has its own persistent directory tree. Create nested folders such as `Block / Courses / Computer Networks / Week 1`, upload into the current folder, and use breadcrumbs to return to any parent. **Move to folder** moves a file or an entire folder subtree within its drive without duplicating file data. Self/descendant moves, duplicate names, and excessive nesting are rejected. Cross-drive moves are not included; download and upload to the other drive instead. Folders are stored as persistent parent-child records in PostgreSQL; disk objects use internal IDs to keep original names and platform paths isolated.

**Refresh storage** reads fresh filesystem measurements. Each drive displays available library space and its allocation usage; expand **Storage details** for total filesystem capacity, system/other/unavailable usage, filesystem free space, and the protected platform buffer. Available space is the smaller of unused allocation and filesystem free space after the buffer and outstanding upload commitments. Existing platform usage is already excluded from filesystem free space.

Before transferring file content, the browser checks the entire selection against fresh storage figures, then the server reserves the new batch atomically. If it cannot fit, or names conflict, none of the new batch starts. Up to **four files upload concurrently**; additional files queue, including selections added while a batch is running. Each file uses bounded **8 MiB chunks** and remains hidden until complete. Progress, speed, and remaining time update while a chunk is being sent. Cancel/retry affects an individual file. Reloaded pages retain incomplete transfer references in session storage; reselect the same original file to resume. Pending reservations expire after 24 hours without a committed chunk. Refresh and ordinary write requests clean expired partial files and completed deletion tombstones.

Multi-GB files are streamed in bounded chunks, never loaded whole into browser or server memory. Slow chunk bodies are received before a database transaction/storage lock is acquired, so they do not block other uploads, downloads, storage checks, or cancellation. Up to eight chunk requests are accepted by each server process, including bodies waiting to commit. Capacity decisions and durable chunk writes still serialize across app instances to protect shared disks. Each chunk allows up to ten minutes to share a slow uplink; Nginx separately closes connections that stop transferring data for three minutes. File downloads use 1 MiB read buffers and support authenticated HTTP ranges, including offsets above 4 GB. Connection speed remains bounded by the user's connection and VM bandwidth. Keep the tab open during uploads; after a disconnect or reload, retry/reselect the original file to continue from the committed offset.

Pending transfers can also be recovered from the server when browser transfer state is lost. Before resuming, the browser checks SHA-256 fingerprints of up to the first and last 2 MB of committed data against the selected original file; this is a bounded identity check, not a checksum of the entire file. A shortened file is rejected instead of being padded with zeros. Shared local filesystems share upload reservations and the stricter platform buffer. Repeat cancel/delete requests are safe after a lost response.

Audio reuses the podcast dock, including seeking and playback position. Both audio and video offer **0.25× through 3× in 0.25× steps**. Video uses a VLC-inspired player with seek, stop, skip, volume/mute, speed, fullscreen, and picture in picture where supported. **Skip (s)** configures the forward/back buttons from 1 to 600 seconds (default 10); the same interval applies to the left/right arrow keys and is remembered for this account/browser. Space toggles playback, F toggles fullscreen, and M toggles mute. Mobile playback adapts to portrait or landscape viewports and preserves the video's original aspect ratio; rotate the phone in normal or supported fullscreen playback. Fullscreen uses the platform's native video fallback where custom fullscreen is unavailable. Browser media is streamed directly with authenticated byte ranges; no server transcoding or media-processing dependency is installed. MP4/MKV files can be uploaded and downloaded; playback depends on browser container/codec support. If playback fails, download the original to open in VLC.

## Organization, learning and support

The global upload tray stays available when navigating to lessons or other platform pages. It supports pause/resume/cancel, pausing/resuming all, and moving queued files to the front. Network failures retry up to five times with backoff; reconnect wakes waiting transfers. Keep the tab open. After reload, reselect each original file to resume its saved offset. Closing the tab does not continue a background upload. Select up to 100 files per batch; additional batches can be added during transfers.

**Upload folder** preserves relative directories. Choose **Keep both**, **Skip existing**, or **Replace safely** before selecting files. Replacement keeps the original available until the new upload completes and requires enough temporary free capacity for both. The original bytes are then permanently removed; public links, notes, favorites, bookmarks and lesson attachments follow the replacement. Every selection passes atomic storage preflight before any file bytes transfer.

Use **Search all folders · Recent · Favorites** across both drives with type, decimal MB size and date filters. Select items for streamed ZIP download, move or permanent deletion. ZIP downloads support ZIP64 without creating temporary archive copies. PDF/images open in a preview; selected video details attempt a small browser-generated thumbnail when the codec is supported.

**History / Undo** reverses rename and move metadata while the item still matches the recorded change. Notes also offer Undo immediately after removal. There is **no Recycle Bin**: permanently deleted bytes and replaced originals cannot be restored by Undo. Confirmations explain permanent deletion.

File Details offers personal **Notes / Timestamp**, favorites and Admin **Attach to lesson**. Lesson dialogs provide **Notes & resources** for their attached files and personal notes. Playback positions and speeds sync through account bookmarks across devices; guest public playback stays in that browser. Video speed uses a 0.25×–3× slider. Controls hide after three idle seconds while playing, reappear on interaction, and stay visible when paused. The first tap on hidden video controls reveals them; the next tap can pause. Keyboard-focused controls remain visible for accessibility.

**Help → My reports** lists a user's own reports and Admin replies. **Admin → Reported issues** lists submitted issues with page/lesson/file context, status, priority and response controls. Report a problem from Help, file details or a lesson. Reports never expose another user's report to learners.

## Setup

Set `LIBRARY_OWNER_ID` to the existing owner's account UUID. Access fails closed when missing. Only the owner and explicitly granted accounts can access the private Library; anonymous visitors need an active public file or directory link. The configured Library owner is the default root Admin; PLATFORM_ADMIN_ID optionally specifies another root UUID. Startup persists that account’s Admin role. On a local installation, add the UUID to the ignored `.env`, run `npm run db:migrate`, and restart. Local roots default to `runtime/library/boot` and `runtime/library/block`; these are development data and share the host filesystem. Back them up before clearing runtime files. Production roots must be durable directories outside release trees.

On the current Ubuntu VM, deploy code/migrations with the normal pipeline, then run as an administrator:

```bash
sudo bash deploy/configure-library.sh OWNER_ACCOUNT_UUID
sudo systemctl restart csquest
```

Run the script from the deployed release (or a reviewed copy). It creates `/var/lib/csquest-library` and `/srv/csquest-data/library` with service ownership and private permissions, configures the immutable owner UUID and systemd write permissions, and configures Nginx transfer streaming without replacing TLS settings. It requires the existing distinct block mount and never formats or clears volumes. Library routes allow 9 MiB request bodies for bounded 8 MiB chunks, with upload and download buffering disabled so transfers do not spool to the boot volume. Other routes keep their existing 4 MB limit. Root-owned provisioning changes require administrator execution; ordinary release deployment does not install root scripts automatically. To upgrade an already configured VM, run `sudo bash deploy/configure-library-transfers.sh` **before** deploying code that advertises 8 MiB chunks. This script backs up the active proxy configuration, validates Nginx, and restores the previous configuration on validation/reload failure.

The application verifies roots and mount identity for each operation. It never creates production roots or falls back onto Boot when Block is missing. Fixed allocations are application-wide and include in-progress file reservations. Platform buffers are `max(5 GiB, 10% of filesystem capacity)` on Boot and `max(15 GiB, 10%)` on Block. Filesystem usage from outside CSQuest can change at any time, so each chunk checks actual free space and may pause to protect the platform.

The current Oracle VM also uses the kernel-provided **BBR** TCP congestion control after a live comparison showed severe throughput loss with CUBIC on the connection to the test location. A 9,437,255-byte authenticated download then completed in about 13 seconds; the preceding CUBIC attempt transferred only 728,713 bytes before the client's 30-second test deadline. This is one observed Internet path, not a guaranteed rate or VM bandwidth benchmark. Existing TCP connections retain their previous algorithm until reconnected. This uses the [Linux kernel's BBR implementation](https://github.com/torvalds/linux/blob/master/net/ipv4/tcp_bbr.c); the existing fair-queue discipline, firewall, routes, and interface MTU are unchanged.

For an explicitly reviewed VM setup, first record `sysctl -n net.ipv4.tcp_congestion_control` and back up any destination files, then `sudo modprobe tcp_bbr`, install `deploy/library-network.modules` as `/etc/modules-load.d/csquest-library-network.conf` and `deploy/library-network.conf` as `/etc/sysctl.d/99-csquest-library-network.conf`, and apply only that file with `sudo sysctl -p /etc/sysctl.d/99-csquest-library-network.conf`. Verify new HTTPS connections and health checks. To undo, restore the backed-up files (or remove these two newly installed files), and set `net.ipv4.tcp_congestion_control` to the recorded previous value; this VM's previous value was `cubic`. No application or VM restart is needed. Normal application release deployment does not change kernel network settings.

Run **`npm run library:storage`** for a read-only JSON diagnostic using the same measurements and accounting as the API. On the VM run it as `csquest` from the active release, with the service's environment settings. It reports actual filesystem total/free bytes, current Library usage and reservations, buffers, quotas, decimal units, and whether both roots share a device. It creates no directories, deletes no partial files, and returns a nonzero exit code if a drive cannot be verified. Node's built-in `statfs`/file-stat APIs provide these measurements; no cloud API credentials, `df` subprocess, or additional disk utility package is required. Both mounted filesystems are measured independently in production; Boot measurement does not depend on Block being online. Missing/unverified Block storage has no fabricated capacity.

The service-managed roots are opaque object stores. Do not add, rename, or edit their contents manually. PostgreSQL holds original names, folders, owner IDs, upload offsets, and sizes. Chunk writes are fsynced before recording their committed offset; retry truncates uncommitted tail data. Deletion first commits a tombstone, allowing cleanup after a crash. Ready files are immutable except their display names. Streamed data is never executable content. PDF and supported raster images can preview inline; HTML/SVG and other files download as attachments.

## Backups and recovery

The normal database export includes Library metadata but does not copy file bytes. For a consistent backup, stop `csquest`, export the database and copy **both** library directories preserving opaque filenames, then restart. Store a verified copy off the VM. Restore the database and its matching binary snapshots together while the service is stopped, restore service ownership/private permissions, verify file counts/sizes and sample downloads, then start. Deployment backups alone are insufficient to recover uploaded files. Do not run automatic deletion of releases/backups as part of Library storage management.

## Validation

`node --test tests/library.test.mjs` checks authentication, owner isolation, origin protection, allocation accounting, batch rejection before file creation, concurrent reservations across two servers, resumable offsets, interrupted-write recovery, range/HEAD/download responses, missing mounts, expiration, cancellation, and zero-byte files. `node tests/library-browser.cjs` exercises desktop/mobile themes, folders/uploads/downloads, capacity rejection, the shared audio dock, and video controls against an isolated test schema and temporary storage.

`node --test tests/library-edges.test.mjs` adds file corruption, shared-disk accounting, malformed input, lost browser state, duplicate chunks, a disconnected upload, storage pressure, folder races, hostile filenames, hard links, a killed/restarted server process, inode exhaustion, missing files, and selected-file metadata. `node tests/library-real-life-browser.cjs` checks six widths in both themes, details panels and decimal units, preflight rejection, loss of a committed response, resume identity checks, deleted folders, and real MP4 playback. Screenshots and JSON reports are saved under `qa-results/library-real-life`; they use temporary test data and small fixture quotas, not live VM capacity.

Local development requires restarting the Node server after server module changes. Serving fresh browser assets from an old server can cause missing-module startup errors. Local test results do not replace post-deployment checks of Linux mounts, systemd permissions, Nginx, and actual uploaded MKV codecs.

`node --test tests/library-transfers.test.mjs` verifies slow-sender isolation, cancellation during a body transfer, parallel files, the 8 MiB limit, and bounded resume fingerprints. `node tests/library-parallel-browser.cjs` verifies four active transfers, queued files, new selections while uploading, desktop/mobile progress, and downloaded contents. The opt-in `node tests/library-large-transfer.mjs` writes **5 GB and 4 GB files concurrently** into isolated temporary storage, resumes through another server instance above the 2 GB offset, then concurrently downloads and SHA-256 verifies both entire files and checks tail ranges beyond 4 GB. It requires 12 GB of temporary free space, cleans up its files/schema, and reports time and peak process memory under `qa-results/library-large-transfer/report.json`.

`node tests/library-video-mobile-browser.cjs` records real portrait and landscape MP4 fixtures and checks five mobile portrait/landscape viewport sizes, fullscreen, arbitrary skip intervals and bounds, keyboard skips, saved settings, and all twelve playback speeds. This is Chromium/Edge emulation; physical iOS/Android fullscreen behavior and rotation remain subject to browser support and device orientation settings.

The additive 006 migration introduces platform roles, preferences, notes, resources, reports and metadata Undo. Run `node --test tests/platform-tools.test.mjs` for permission/privacy/organization/public-directory checks, and `node tests/platform-tools-browser.cjs` for desktop/mobile Admin, learner navigation, retry/tray, notes, favorites, resources, Undo and report-response flows.
